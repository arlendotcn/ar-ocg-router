# 路由决策

[English](routing.md) · [**中文**](routing-zh.md)

每个请求都会解析成一个有序的候选端点列表，路由器按顺序尝试，直到某个端点成功应答。

## 候选顺序

端点被分进若干**桶**，桶的顺序取决于时钟与额度状态：

| 时段 | 套餐额度 | 桶顺序 |
| --- | --- | --- |
| 忙时（现金贵） | 未耗尽 | `plans` → `fallback` |
| 忙时 | 全部耗尽 | `fallback` → （`plans` 仍作最后手段） |
| 闲时（现金半价） | `surplus_first` | `plans-surplus` → `fallback` → `plans-tight` |
| 闲时 | `plans` / `fallback` | 该侧优先 |

桶内：按 `order` 升序。该值由条目位置推导，所以在控制台里拖拽出的顺序就是这里使用的顺序。

第二轮会把剩下所有还能用的都补上作为最后兜底，包括冷却中的端点，除非它主动退出。

## 「充裕」是什么意思

当某个套餐的额度在其窗口结束时**还会有剩余**，它就是充裕的——现在花掉它，等于没有占用
以后会被用到的份额。两条判定：

1. 任一窗口达到 `surplus_max_pct` 即视为**紧张**；
2. 开启 `surplus_projection` 时，按窗口进度线性外推，预计用不到 100% 的也算充裕。

## 失败切换

| 上游返回 | 动作 |
| --- | --- |
| 401 / 403 | 该端点冷却 `auth_cooldown_secs`，换下一个 |
| 429 或额度类错误 | 冷却，并把套餐额度标记为耗尽，换下一个 |
| 400 / 404 / 422 且信息像是模型问题 | 换下一个（由 `retry_on_model_error` 控制） |
| 400 / 404 / 422 其它 | 原样返回客户端——参数错误不能被掩盖 |
| 5xx、超时、连接失败 | 短暂冷却，换下一个 |
| 全部候选失败 | `502`，并附每个端点的失败详情 |

单个请求最多尝试 `max_attempts` 个端点，并在 `attempt_budget_secs` 后停止。

## 钉住某个端点

客户端传来的模型名不参与选路，只有一个例外：它可以钉住单个端点。

| 客户端写 | 效果 |
| --- | --- |
| `ar-ocg-router` | 正常路由 |
| `deepseek-flash`（任意其它值） | 同样正常路由，该值只记日志 |
| `go-dsf/x` | 钉住名为 `go-dsf` 的端点 |
| `generic/model-c` | 按 provider + 模型钉住 |

钉端点会跳过策略、跳过状态与禁用开关：那是一次明确的、针对单次请求的指定。

## 禁用端点

`enabled: false` 会把该端点从**所有**候选列表移除，包括失败兜底那一轮。
这是真正的停用开关，不是降低优先级。想保留它、只是偶尔使用，请改它的 `rule`。

重新启用后会恢复该侧的自然默认：套餐端点重新可作首选，现金端点回到
`[offpeak, quota_low]`。

## 流式

流式（SSE）响应逐块转发、不缓冲不修改，同时旁路解析尾部的 usage 做统计。
重试链只在首字节写出之前有效；响应头一旦发出，该次响应即已确定。
