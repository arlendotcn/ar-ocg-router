# 模型库

[English](model-library.md) · [**中文**](model-library-zh.md)

一个端点 = 一个商家 + 一个模型，而同一个模型在不同商家那里用不同的 id 售卖，实际限制也不同。
模型库记录每个模型已知的参数，让控制台能把限制显示在端点旁边，并把「模型 ID」从打字测试
变成点选。

它存为 `models.library.json`，位于 `config.yaml` **同级目录**，而不是配置里面。这一点很关键：
控制台每次保存都会重新生成 `config.yaml`，写在里面的内容会被重写或丢失。
有测试专门钉住这个行为。

模型库只作参考，路由器从不据它选路；端点上的 `model` 字段才是实际发出的内容。

## 字段

| 字段 | 含义 |
| --- | --- |
| `id` | 网关内使用的规范名。 |
| `label` | 给人看的名字；留空则用 id。 |
| `aliases` | 同一模型在各家使用的不同 id，例如 DeepSeek 官方的 `deepseek-flash` 与部分国内套餐的 `deepseek-v4.1-flash`。用于把实测清单归并到同一条目。 |
| `context_tokens` | 单次调用能接受的最大 token 数（含输入与输出）。 |
| `max_output_tokens` | 单次回复最多生成多少 token。 |
| `reasoning_levels` | 该模型接受的思考强度档位，从弱到强。支持关闭思考时写 `none`。 |
| `input_modalities` / `output_modalities` | `text`、`image`、`audio`、`video`。 |
| `notes` | 任何容易忘记的事实：实测坑、白名单限制、计费特点。 |
| `tags` | 用于筛选归类，例如 `deepseek`、`vision`、`long-context`、`plan`。 |

值为 `0` 表示「未知」，界面上显示为破折号而不是一个假数字。

## 模型点选

端点编辑里的「模型 ID」字段有一个**拉取列表**按钮，会真的请求
`GET /api/endpoints/<名>/models`。结果按模型库排序：已知模型在前、上下文大的在前，
未知的按字母序在后。每行显示上下文大小与非文本模态。点一行即填入，下方显示解析到的参数。

清单只是建议，不是约束——上游会列出自己调不通的 id，也会漏掉能用的 id
（见 [上游事实](upstream-zh.md)），所以输入框始终可自由填写。

## 默认内容

二进制内置十个模型，覆盖 DeepSeek 家族与常见套餐模型，所以全新安装立刻就有可用的限制信息。
从控制台保存会写出该文件；删掉它即回落到内置集合。
